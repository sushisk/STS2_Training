# Stable Frontier Pruner RL Fine-Tuning

This stage starts from the supervised stable-pruner artifact from PR #50 and keeps the
search-control surface narrow: only stable/resolved frontier survivor choice is explored.
Policy candidate generation, continuation handling, beam width, stopping, parent scheduling,
and Whole Run active-branch capacity remain unchanged.

## One-line learning entrypoint

The normal input is the logs emitted by the current Training code. Manual conversion to a
training CSV/custom JSON schema is not required. After `pip install -e ".[train]"`, use the
console command below; the equivalent module form is
`python -m sts2_training.runner.stable_pruner_learn ...`.

The two explicit selectors are independent:

- `--learn supervised|rl` selects the learning objective;
- `--start fresh|resume` selects whether coefficients start from zero/new fitting or from an
  existing artifact.

Both also accept `auto` as the default.

### Supervised from zero

```bash
stable-pruner-learn data/logs --learn supervised --start fresh
```

This recursively discovers `.jsonl`, `.json`, `.log`, and `.txt`, extracts current
`combat_oracle_decision` Oracle v3 records, normalizes prefixed/suffixed log lines internally,
and runs the #50 pairwise logistic trainer. The default output is
`tools/output/stable_pruner_weights.json`.

### Continue supervised learning

```bash
stable-pruner-learn data/new_oracle_logs \
  --learn supervised --start resume \
  --weights tools/output/stable_pruner_weights.json
```

Supervised resume keeps the existing artifact's feature scale and coefficients and applies
weighted pairwise logistic gradient updates to new Oracle v3 data. By default it inherits
`min_target_gap`, terminal weight, and bootstrap weight from the artifact. Teacher provenance
must still match unless an explicit mismatch override is requested. Resume history is appended
as `supervised_finetuning_history` instead of erasing the original supervised/Oracle provenance.
`--epochs` controls supervised resume passes only.

### Continue on-policy RL

```bash
stable-pruner-learn data/rl_logs \
  --learn rl --start resume \
  --weights tools/output/stable_pruner_weights.json
```

RL extracts `stable_pruner_rl_episode` trajectory v2 records and performs exactly one REINFORCE
batch update. The exact behavior artifact SHA contract remains mandatory. `RL + fresh` is
intentionally rejected: a saved trajectory was generated by a specific behavior artifact, so
pretending it came from a zero/fresh policy would violate the on-policy contract. To start RL
from a new model, first create a supervised artifact, collect fresh trajectories under that
artifact, then run RL resume.

### Auto mode

The shortest initial command remains:

```bash
stable-pruner-learn data/logs
```

With no `--weights`, this resolves to `supervised + fresh`. With `--weights`, start resolves to
`resume`; if the input contains only Oracle records it chooses supervised resume, and if it
contains only RL records it chooses RL resume. If both learnable record types are present while
resuming, the command requires explicit `--learn` instead of guessing which objective to run.
Records belonging to the other stage are reported as deferred rather than silently mixed.

The entrypoint uses temporary normalized JSONL only for the duration of the command. Before
finishing it rewrites artifact paths back to the original logs and adds
`one_line_learning_ingest` with original source-log SHA-256 values, record counts, selected
learning/start modes, normalization contract, and current schema versions.

## Upstream contract

RL consumes the public stable-pruning contract directly; it does not define another node
adapter or depend on `BeamNode`.

Current versions are:

- learned-pruner artifact schema: **v2**
- `StablePruneNodeView` schema: **v1**
- stable-pruner feature schema: **v2**
- RL trajectory schema: **v2**

`PlackettLuceLinearStableFrontierPruner.select()` accepts
`Sequence[StablePruneNodeView]` plus `StablePruneContext` and returns ordered frontier
indices. The returned index order is the Beam survivor order, exactly as required by the
upstream `StableFrontierPruner` contract.

## Stochastic top-K policy

The supervised artifact already provides one linear score per stable node. RL therefore does
not learn pruning from scratch. `PlackettLuceLinearStableFrontierPruner` samples an ordered
choice without replacement from those scores.

The sampled Plackett-Luce order is the stochastic action used for REINFORCE. The sampled set
is then returned to Beam in deterministic supervised-score order, so exploration changes the
survivor set without additionally randomizing expansion scheduling.

When `frontier_size <= beam_width`, every node survives. There is no stochastic pruning action,
so no RL step is emitted and the wrapper returns the ordinary supervised score ordering.

## On-policy trajectory collection

Use the real emulator and the existing fixed-seed A/B harness:

```bash
python -m sts2_training.runner.stable_pruner_rl \
  --scenario data/scenarios/slime.json \
  --weights tools/output/stable_pruner_weights.json \
  --seeds 101,102,103,104 \
  --temperature 1.0 \
  --output tools/output/stable_pruner_rl_batch.jsonl
```

For each seed, the baseline arm uses `ValueTopKPruner`, the learned arm uses a fresh
stochastic wrapper around the exact input artifact, and arm order alternates. Only learned-arm
stochastic stable-prune decisions are recorded. The paired terminal outcome plus optional
search-cost deltas form the episode reward.

Optional penalties are `--node-cost-weight` and `--beam-ms-cost-weight`:

```text
(learned_outcome - baseline_outcome)
- node_cost_weight * (learned_nodes - baseline_nodes)
- beam_ms_cost_weight * (learned_beam_ms - baseline_beam_ms)
```

Victory/Win maps to 1 and Defeat/Loss maps to 0. Unknown outcomes and episodes without an
actual pruning choice are excluded from the RL batch.

## Trajectory schema v2

Every episode record identifies the exact behavior contract:

- behavior artifact SHA-256;
- artifact schema version;
- `StablePruneNodeView` schema version;
- feature schema version;
- stochastic pruner name/version;
- temperature and sampler seed;
- scenario-template SHA-256 and Beam configuration;
- paired outcome/search-cost diagnostics and scalar reward.

Every stochastic prune step stores:

- node-view schema version and feature schema version;
- stable-prune context fields;
- the complete feature matrix used by the behavior scorer;
- behavior scores;
- ordered Plackett-Luce `sampled_indices`;
- deterministic `returned_indices` survivor order;
- exact selection log probability.

Opaque decision-local action IDs, branch IDs, RNG IDs, DTO payloads, and other Beam internals
are not part of the RL feature contract.

## One update per fresh RL batch

Before computing an RL gradient, the updater verifies trajectory schema v2, exact behavior
artifact SHA, artifact/node-view/feature schemas, recomputed behavior scores, sampled indices,
deterministic returned survivor order, and the Plackett-Luce log probability. Any mismatch is a
hard error rather than an off-policy approximation.

The update is the episode-level REINFORCE estimator:

```text
gradient = mean_episode(
    paired_reward * sum_prune_step(grad log pi(sampled_top_k | frontier))
)
```

The RL updater intentionally has no multi-epoch option. After an artifact changes, the previous
trajectory batch no longer matches its SHA and cannot be reused. The intended loop is:

```text
supervised/current artifact
    -> collect stochastic paired trajectories
    -> one REINFORCE update
    -> new artifact
    -> collect a fresh batch under the new SHA
    -> repeat
```

## Artifact provenance

Artifacts remain learned-pruner artifact schema v2 and loadable by
`LinearStableFrontierPruner`. Existing supervised training metadata and Oracle teacher/dataset
provenance are preserved. Supervised resume appends `supervised_finetuning_history`; RL resume
appends `rl_finetuning_history`. The one-line ingestion layer additionally records the original
source logs and their hashes.

## Promotion boundary

This PR does not automatically promote an updated pruner. Held-out Oracle diagnostics and
fixed-seed real-emulator A/B evaluation remain separate gates. A lower supervised batch loss or
a positive RL training-batch reward alone is not evidence of general gameplay improvement.

## Still out of scope

This stage does not learn dynamic beam width, parent expansion scheduling, continuation
allocation, stopping, PolicyModel action proposal, Whole Run capacity, or arbitrary set-network
selection. Those belong to a later `SearchController` abstraction rather than widening the
stable-pruning seam.
